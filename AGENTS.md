# Copilot Credits

VS Code extension showing the signed-in account's Copilot credit use in a status bar item and its hover. Accurate credit spend and accurate account usage matter above all. Entry point: `src/extension.ts`, bundled by esbuild to `dist/extension.js`.

## How to work

- **Grounded approach.** Decide each approach from the real logs on this machine, Copilot Chat's bundled source and the VS Code API. Tag `v0.0.6` holds the old build (`git show v0.0.6:<path>`), an audit source for user-visible details and hard-won fixes.
- **Normal path first.** Several open windows, restarts, account switches and a new month must simply work. Anything rarer gets a sane fallback: a briefly wrong or missing value that the next update corrects is fine. Guard only against values that would stay wrong, and against crashes.
- **Lean code.** Use the fewest files and plain functions that stay correct. Add a class, cache, layer or abstraction only when VS Code requires it or a measurement shows the need.
- **Local only.** Read files on this machine. No network, no GitHub sign-in, no telemetry.
- **Decide plumbing, ask about looks.** State the approach in 2-3 lines before coding. Decide robustness and internals yourself. Ask Leon before changing anything he sees.
- **Tests that bite.** Write focused tests for parsing and math: quota lines, the account, today and daily values, the model tally, number formatting. Break the code under each new test once and confirm the test fails.
- **Finish the change.** Run `npm run compile`, `npm test` and `npm run package`, and confirm `npx vsce ls` lists only shipped files. Have a subagent review the diff. Then give Leon `npm run install:local` and the checks. Commit only when Leon asks.

## Design

- **Status bar:** `3.1% • 76.5/100%`, today's share of the monthly allowance, then the month used out of 100%. Past the allowance: `3.1% • 100/103.2%`. No icon, no words, no click. At startup it shows the saved numbers at once. Other states: `Waiting for Copilot` with nothing saved, `Restart to see Credit usage` with nothing saved while this window's Copilot Chat logs below Trace, `Unlimited Copilot quota` and `No Copilot credit allowance`.
- **Hover,** in sections split by `---`:
  - Today: bold label, today's share and credits (`3.1%  (2 480)`); on the right the account in the description color, then the info link.
  - Month: bold label, `76.5% / 100%  (61 200 / 80 000 credits)`, or `100% / 103.2%  (80 000 / 82 560 credits)` past the allowance; on the right `100.9% monthly pace`, projected at the latest reading's time, or `Pace unavailable` unless the reset is at the start of the next UTC month and has not passed. Below it, the account's last 30 days, one bar per day with the sizes, theme palettes and height scaling in `hover.ts`, earlier months dim, the first and last date underneath, and the bar label `23 Sep · 3.1%` or `23 Sep · Not tracked`.
  - Model use this month: the top 3 models by credits across every account, `1. model` with `N sessions · 94%` (`1 session` for one chat), the share being of all credits recorded this month. Hidden until something is recorded; shown alone before the first quota reading.
  - Unlimited and zero allowances show one row: the label, the account and the info link.
- **Numbers:** a non-breaking space between thousands, at most one decimal, no trailing zero. In the hover, a tiny positive share reads `<0.1%`.
- **Quota data:** every window reads the `[ChatQuota]` lines of every window's output log in the running session. A reading belongs to its log's latest account line, else the latest account line of any window before it, else the saved account. The saved record per account holds its earliest reading, or the newest one older than 35 days, then each local day's last reading; an account without a reading in 35 days is dropped. Today is the latest reading minus the last one before local midnight; a day's bar is its last reading minus the one before; a day without a reading shows 0% and the next day with one absorbs the gap; a monthly reset counts from zero.
- **Model use data:** `llm_request` lines in Copilot's debug logs with a positive `attrs.copilotUsageNanoAiu` (credits = value / 1e9), bucketed by the local month of `ts`. A chat is one `debug-logs/<id>/` folder and every `.jsonl` in it. The saved monthly tally keeps what it saw after Copilot prunes or trims its logs, and counts a request once by its chat, `ts` and `spanId`.
- **Setup,** silent and leaving a value the user set alone: at startup, set `github.copilot.chat.agentDebugLog.fileLogging.enabled` to true and delete the old build's stored data; once this window's Copilot Chat log is written, set Copilot Chat's default log level to Trace.

## Facts

Checked on 2026-09-24 against VS Code 1.139 and its built-in Copilot Chat 0.67. Re-check each fact you rely on.

- **Output log:** `%APPDATA%\Code\logs\<session>\window<N>\exthost\GitHub.copilot-chat\GitHub Copilot Chat.log`, beside a separate `GitHub Copilot Chat Hooks.log`. Lines read `2026-09-23 10:04:50.301 [trace] message` in local time with CRLF endings, and multi-line messages continue without that prefix. A window reload keeps `window<N>` and appends to the same file.
- **Rotation:** at 5 MB the log is renamed to `.1.log`, up to `.6.log`. When the rename fails, as it did on this machine, the file is emptied in place, so a log can shrink at any moment and lose its first lines, account line included.
- **Short-lived sessions:** VS Code keeps the current log session plus the 9 newest and deletes the rest 10 seconds after each start. Every `code` command-line call, `npm run preview` included, adds a session folder.
- **Quota lines** appear only at Trace: `[ChatQuota] processQuotaHeaders` on every HTTP chat response, `processUserInfoQuotaSnapshot` after each new Copilot token, and `processQuotaSnapshots` on WebSocket turns. Each carries flat JSON with `quota`, `percentRemaining`, `additionalUsageUsed`, `resetDate`, `unlimited` and `hasQuota`, in varying key order. `percentRemaining` has one decimal and lags: it stays flat through dozens of requests, then drops several tenths at once. Personal allowances reset at 00:00 UTC on the 1st; without a server reset date, Copilot invents one a month ahead.
- **Account line:** `[info] Got Copilot token for <login>` comes before the quota snapshot of that token. It appears at window start and when a new token is fetched, so a long-running window logs hours of readings after one account line. Anonymous access logs the literal word `devDeviceId`. Enterprise managed logins contain `_`.
- **Trace:** `workbench.action.setDefaultLogLevel` with `(1, 'github.copilot-chat')` saves the default in argv.json. It switches only the calling window's existing Copilot Chat channel, and only while that channel sits at the previous default. Other open windows, reloads and windows opened from inside VS Code keep their startup level until VS Code is quit and reopened. A window opened with the `code` command reads argv.json afresh. No Copilot setting controls its log level.
- **GPT models are missing from the output log:** their Responses API requests write no request or cost lines there. The debug logs have them, and the quota still counts their spend.
- **Units match:** the quota's unit matched the debug-log credits.
- **Debug logs:** `%APPDATA%\Code\User\workspaceStorage\<id>\GitHub.copilot-chat\debug-logs\<chat>\`, or the profile's `globalStorage\github.copilot-chat\debug-logs\` for windows with no folder open. A chat folder holds `main.jsonl` plus `title-*`, `runSubagent-*` and `searchSubagent-*` logs, flushed every 4 seconds, beside `models.json`, `tools_<n>.json` and `system_prompt_<n>.json` snapshots. Copilot prunes a folder to 50 chats only when that window starts a chat, so a folder can hold 51, and trims files over 100 MB to their newest 60 MB, which can cut the first line. The logs name no account. The debug log setting takes effect after a window reload, and a Copilot experiment can set its default.
- **Request costs:** most `llm_request` lines carry a positive `copilotUsageNanoAiu`. Free models log 0, and failed requests omit the field. `ts` is the request's start in epoch milliseconds. `spanId` is a counter that restarts at 1 in every window, so only `ts` with `spanId` tells requests apart.
- **Profiles:** another profile's global storage sits under `User\profiles\<id>\` or deeper, like `profiles\builtin\agents`, while every profile shares `User\workspaceStorage`.
- **Status bar:** Copilot's own item is anchored right of the language mode (priority 100.1); priority 100.05 lands directly right of it.
- **Hover limits:** the hover keeps tables with `align`, `colspan` and `width`, `img` tags with `data:` URIs and `width`/`height`/`title`/`alt`, and `span` styles written exactly like `color:var(--vscode-descriptionForeground);`. It stays open under the mouse only while its markdown contains a link. Each `statusBar.text` or `tooltip` assignment sends the window an update; VS Code redraws an open hover only when the markdown differs.
- **Copilot Chat's source** ships with VS Code at `resources\app\extensions\copilot\dist\extension.js` under the install folder.
